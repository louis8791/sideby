# Phase 1B 本機驗證紀錄

日期：2026-09-04。範圍：使用者負責的應用後端第一批；全部請求均為合成資料。

## 已觀察結果

- Windows x64、Node.js 24.16.0、Next.js 16.3.4、PostgreSQL 18.4。
- `npm run build`：正式建置通過，包含 TypeScript 檢查。
- `npm test`：11 個行為子測試＋1 個整合父測試，共 12 passed、0 failed；最後一次約 5.1 秒。
- 測試使用真正 PostgreSQL 與 `next start` 正式產物，經 HTTP 呼叫；沒有以資料庫／HTTP mock 代替。
- 雙 SSE 訂閱的最後一次本機樣本：514ms。這只是一筆合成樣本，不是 p95、手機網路或負載效能承諾。
- `npm run dev:local`：實際啟動後匿名入口回 201；Ctrl+C 關閉啟動的應用程序與資料庫。已修正 Windows pg_ctl 管線造成的額外等待及 Ctrl+C 關閉競爭。

## 行為覆蓋

| 行為 | 觀察 |
|---|---|
| 匿名憑證 | 缺少／無效／到期拒絕，資料庫存雜湊 |
| 同時加入最後一席 | 兩個請求只有一個成功，總成員維持兩位 |
| 非成員 | GET、PUT、confirm、events、建立 Session 均拒絕 |
| 輸入邊界 | 未知／冒名／私密欄位、過大 body、跨夜、負預算拒絕 |
| 同時修改 | 只接受當期 version；另一請求回版本衝突 |
| 雙方確認 | 一人不能代兩人完成，編輯後兩方確認清除 |
| 即時公開資料 | 兩訂閱收到新條件，重連取得最新快照 |
| 公開隔離 | 固定欄位回應不含憑證、邀請碼或輸入 canary |
| 在線狀態 | 30 秒未活動後到期，有效讀取後恢復 |
| 持久化 | migration 重跑與應用重啟後版本、共同條件仍在 |
| 故障 | 查庫失敗回安全 503，恢復後可讀；回應不洩漏 SQL |
